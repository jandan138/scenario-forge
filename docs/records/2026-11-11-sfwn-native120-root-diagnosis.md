### 后续排除与数值求解对照

摩擦起效阈值 0.003m 的初始化对照已确认原生采用，完整执行 3981 条动作且无状态报警，但两指仍分别出现约 19.96mm、17.41mm 穿透，不能交付为修复。原设置的新完整观测覆盖了之前 PVD 休眠位姿缺失的区间：3259 条 getter 位姿均与物理时钟对应，首次穿透仍在第 3182 步，3170 步之前未见本次两指/门板检查范围内的重叠。对齐程序已修复故障尾段重复使用同一 command 编号时的键覆盖问题，改为按该编号内的物理采样出现次序匹配；新增回归测试通过，穿透数值未改变。

不能将所有穿透单独归因于关节读数被限位截断：位置迭代 255 的对照在首次约 13.19mm 穿透时，右指 q 与几何位移均约 34.51mm，位于 0–44mm 限位内部；Multiply 对照首次约 8.09mm 穿透时也在限位内部。该证据只排除过度单一的解释，不排除限位与接触耦合在原异常中的作用。见 `reports/FIRST_OVERLAP_JOINT_LIMIT_CONTEXT.json`。

完整摩擦报告已确认观测中性：新基线全部 3259 行机器人记录与原基线一致，仍在第 3227 步报警。异常前报告了 4415 个有限的摩擦锚点，其中 1751 个有非零冲量。对于所审窗口中法向冲量总模长大于 1e-4（接口冲量单位）的样本，摩擦锚点冲量模长之和与 `2 × 法向冲量模长之和` 的最大比值约为 1.0000007；没有据此发现摩擦系数被简单错误放大的证据。个别零法向报告仍带小摩擦报告的情况保留待解释，不直接宣布违反库仑定律或能量守恒。

参数含义按版本化源码补充：[TGS 接触准备](https://github.com/NVIDIA-Omniverse/PhysX/blob/f07ba77f2d8af805824385b4616549974d231a8d/physx/source/lowleveldynamics/src/DyTGSContactPrep.cpp#L1354) 将 `frictionOffsetThreshold + restDistance` 传给摩擦锚点生成；旧锚点另经复用判断。因此 0.003m 不是已证明的绝对 3mm 摩擦截止距离，更不是关闭跨步摩擦记忆。该公开 CPU 源码不冒充当前 GPU 二进制的逐行证明。

相关距离设为 0 的短测被当前 SDK 判为非法，场景回退到默认参数，原生观测为 PGS、相关距离约 0.025m，并出现 CPU 场景不支持 SDF 刚体的日志。它已被剔除，不计作物理反例。版本化 `PxSceneDesc::isValid` 也明确拒绝非正相关距离，尽管 USD schema 文案范围写作 `[0, inf)`。后续采用合法的 1e-6m 单变量短测；核验器增加原生 GPU dynamics 标志检查，禁止以场景回退结果冒充目标配置。

另一个有界数值对照保留原材质、碰撞 offset、质量、惯量、驱动增益与力上限，通过普通 YAML 设置 `EnableExternalForcesEveryIteration=true` 和 `MinPositionIterationCount=255`。短测已确认原生采用，完整回放正在执行；尚未通过重复、撤销与功能验收，不作已修复声明。所有新控制均留在个人诊断目录，源输入和 Scenario Forge 核心未改，规范仍无需推广性变更。
