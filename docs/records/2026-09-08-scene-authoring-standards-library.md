# Scene-authoring standards library and maintenance workflow

## Decision

`docs/standards/` is the current source for scene-authoring rules covering asset
intake, USD organization, articulation, materials/liquids, task state, validation
and delivery. Core package/schema/API contracts keep their existing design
authority. Rules distinguish mandatory requirements from recommendations,
carry stable IDs/anchors, scope and evidence references, and use Git commits
for versions rather than a separate registry.

The scope explicitly includes articulation. Canonical Instance v2 requirements
are scoped to the qualified fixed-base route; oven evidence is not generalized
to mobile bases or all articulation topologies. Titration r1.6 and Fehling r2
provide material/state examples, not universal articulation qualification.

The same implementer updates applicable rules, design references, operations
instructions and records after validation appropriate to the change. Unverified
ideas remain proposals. If a task changes no general rule, its record explains
why. This is a workflow obligation, not a background synchronization process,
new CI gate, schema registry or extra approval requirement.

## Authority and migration

- `docs/design/articulated-instance-layout.md` retains rationale, legacy context
  and evidence links; its current authoring rules move to ART-001 through ART-006.
- Tabletop authoring constraints move to USD-006. The domain identifier,
  exception metadata and evidence interface remain in its design document.
- VR export instructions retain commands, options, profile/API details and
  acceptance context; hierarchy, registration, materialization and collision
  authoring requirements reference the canonical rules.
- Artifact Policy's Git/output/retention rules move to VAL-005 and VAL-006 without
  changing their meaning. The old operations path remains a navigation/procedure
  entrypoint.
- Core compiler, source-binding, material-admission, overlay and fluid capability
  contracts retain their API definitions. The standards cite them rather than
  restating versioned fields and behavior thresholds.

README links the entrypoint. AGENTS and CONTRIBUTING describe the maintenance
responsibility. CONTRIBUTING's SDK-import wording is clarified to match the
existing AGENTS rule and architecture test: pure package layers are protected;
simulator adapter/tool entrypoints remain the integration boundary. This is not
permission to move simulator dependencies into pure modules.

## Adoption and evidence

Initial rules use the existing committed architecture tests, articulation
fixtures, VR materialization/registration tests, and dated titration/water-bath
runtime evidence. Scope, inherited compatibility and visual caveats stay visible.
Documents that describe only capability contracts without implementation evidence
are not presented as completed runtime capabilities.

Historical records and immutable packages are not rewritten. The 2026-08-16
visual-liquid prototype's background-only claim is interpreted within its own
scope; later bounded visual interactions have separate evidence. New work and
future revisions adopt applicable current rules, recording their rules/commit
basis. No historical package is retroactively certified against the new library.

## Validation plan and limits

Only the existing articulation documentation regression test is adapted to the
new canonical location and legacy navigation links. It first failed because the
new standard did not exist, then passed after migration. One-off local reference
and anchor checks accompany this documentation change; they are not installed
as a new synchronization checker or CI gate.

Run `make check` and review linked source/scope consistency. No runtime logic,
package schema, CI workflow, Makefile, simulator scene, asset or delivered ZIP
is changed or regenerated by this documentation migration.

## Final validation

The library has 38 stable rule IDs across six topics, an index and a
maintenance/template page. A one-off check resolved 138 local references
across 19 new/changed documents and validated all rule anchors.
The adapted documentation/structure/VR-registration selection passed all nine
tests. `make check` passed with 946 tests and 1 skip, including Ruff,
package smoke and phase10x smoke. No new synchronization gate was installed.
