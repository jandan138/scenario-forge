# 验证、证据与交付规范

状态：当前。适用范围：场景制作与交付，以及原 Artifact Policy 的生成输出保留政策。

## 强制要求

<a id="val-001"></a>
### VAL-001 — 声明通过的是哪一层

区分静态结构、目标运行时、视觉、场景集成、真实任务执行和机器人策略结果。
生产者合格不替代最终场景集成；运动学指定轨迹通过不等于真实抓取；视觉体积变化不等于真实液体转移。
未验证的能力不能以 `pass`、漂亮截图或案例相似性补齐。
引擎报错后返回的有限旧位姿不证明仿真继续运行；验收需核对引擎健康和记录完整性。
依据：[task09 粉末瓶 r2 的错误与停滞诊断](../records/2026-09-10-task09-powder-bottle-r2.md)。

使用服务进程、worker 或运行时错误回调时，引擎健康检查须覆盖启动、初始化和执行阶段的
原始日志；只检查 worker 或回调注册后的消息，不能声明整个运行无引擎错误。
记录实际检查的日志及遗漏范围。依据：[科学实验五项交付的完整日志复核](../records/2026-10-11-scientific-five-item-acceptance.md#full-engine-log-coverage)。

“未发现错误级日志”不等于“没有警告”或“任务成功”。报告分别保留错误、警告及碰撞降级的
检查范围与结果；警告的影响未确认时，不推断其无害或必然导致任务失败。
基础设施检查的 PASS 不代替成功示范或数据导出资格。
依据：[科学实验阶段收尾](../records/2026-10-12-scientific-repair-checkpoint.md)。

依据：[资产准则](asset-intake.md)、[固定基座记录](../records/2026-09-04-fixed-base-articulated-instance-v2-and-oven-handoffs.md)、
[水浴证据边界](../records/2026-09-08-fehlings-water-bath-r2-sedimentation.md)。

<a id="val-002"></a>
### VAL-002 — 按变化类型验证

| 变化 | 对应验证 |
|---|---|
| 纯规则、数学或状态 | 有意义的边界、暂停/恢复、重置及失败测试 |
| USD 组装、物理/关节 | 结构/引用检查；适用的目标运行时、运动与重置验证 |
| 材质、液体或几何外观 | 实际属性与几何读取；初始/中间/终点等必要视角的渲染检查 |
| 包装或入口 | 依赖闭包、可迁移路径、入口/配置一致性、ZIP 完整性和哈希 |
| 文档或规范整理 | 源依据、适用范围、引用一致性；已有受影响测试和仓库检查 |

验证范围匹配实际改动，不要求每次文档更正重跑所有历史场景。
相应契约规定多次独立冷启动时必须遵守；不能把同一报告复制多份充当独立运行。
本次任务已匹配的证据可沿用，注明来源与复用范围；材质/场景字节变化不能继续把旧场景报告当作新验证。
日常制作遵循已有 `make check` / `make ci-check` 工作流，不改变仓库原来的检查分工。

<a id="val-003"></a>
### VAL-003 — 证据绑定最终内容

运行报告记录实际目标版本及场景/资产身份、哈希和条件。
截图明确是 live capture、静态视觉状态还是保留的实际运行状态回放；后者恢复对应的姿态、粒子、材质和动态几何。
运动学工具也须记录实际物理位姿；控制目标应单独标记，不能替代实际位姿来证明接触过程。
依据：[粉末称重 r1 的记录与回放](../records/2026-09-09-rigid-powder-force-weighing-r1.md)（2026-09-09）。
目视记录说明所看文件、结论、限制及是否独立审查。不能只看初始图片就声明全阶段可用。

资格要求的最终包检查包含依赖闭包、无缺失/包外依赖、ZIP CRC 和 SHA。
打包入口不能把新任务配置改回旧参数。更改最终内容后刷新受影响的证据与校验；
仅改文档且场景字节未变时可保留场景证据，但须同步文档、归档及其哈希。

依据：[滴定最终证据](../records/2026-09-07-titration-r16-single-material.md)、
[水浴最终证据](../records/2026-09-08-fehlings-water-bath-r2-sedimentation.md)、
[闭包测试](../../tests/test_package_closure.py)。

<a id="val-004"></a>
### VAL-004 — 保留检查限制

记录已知反射、遮挡、特定姿态失效和未建立的兼容性。
限定范围内可接受的 WARN 必须与明确的失败分开；任务所需现象看不到或结构不正确时不能用备注掩盖。
如需通过额外视角观察，给出其用途和条件，不把回放观察当作实际操作能力。

<a id="val-005"></a>
### VAL-005 — Git 与大型产物分开

原 `docs/operations/artifact-policy.md` 的正式文件保留规则迁入本条，内容含义保持不变：

- 提交包 manifests、schema、小型示例/fixtures、解释决策的小型验证报告及日期记录。
- 不提交原始 USD 树、转换资产、大型输出、视频/帧/深度数组/模拟器 dump、原始扫描/点云/高斯资产、模型权重。
- 大文件用 [external_artifacts 索引](../../external_artifacts/README.md) 或已声明的外部路径定位。
- 源数据保持不可变；生成输出放在 scratch 或有说明的外部产物位置。
- 外部流水线集成只提交 Scenario Forge 拥有的契约、锁、出处和证据摘要，不能把外部管线变成核心包层。

论文图稿的可编辑交付按作者明确指定的保留范围处理：本仓库在 2026-09-22 收尾时，
作者要求所有历史 PPTX 随代码入 Git，当前最终 SVG/PDF 也保留；未追踪的历史 SVG/PDF
与渲染缓存留在本地并记录路径、大小和 SHA-256。此范围仅限论文图稿，不放宽原始 USD、
视频、仿真帧或大型场景包的外部产物规则。已追踪的历史文件不因新增忽略规则被移除。
具体清单见 [图稿保留索引](../../paper/artifact-retention-20260922.json)，
决定与验证见 [全仓库收尾记录](../records/2026-09-22-repository-closeout.md)。

依据：[贡献指南](../../CONTRIBUTING.md)、[Git 忽略规则](../../.gitignore)。

<a id="val-006"></a>
### VAL-006 — 当前交付与历史保留

[当前任务头](../../configs/artifact_retention/current_task_heads.v1.json) 按任务族与 variant 定位，不按最大编号猜测。
每个头同时保留完整生成目录和对应 canonical ZIP。其他输出按既有政策明确分类：

| 分类 | 意义 |
|---|---|
| `KEEP_HEAD` | 当前任务/variant 交付 |
| `KEEP_SOURCE` | 当前构建依赖或来源绑定 |
| `ARCHIVE_SUPERSEDED` | 已被明确的新头替代 |
| `ARCHIVE_DIAGNOSTIC` | 有价值但非活动的诊断 |
| `DELETE_REBUILDABLE` | 可机械重建的数据 |
| `HOLD` | 状态不明，不自动归档或删除 |

OSS 归档保持追加且不可变，使用项目拥有的 `artifact-history-v1/<family>/<variant>/<revision>/<batch>/` 命名空间，
保留文件/树哈希并做恢复抽查；仓库验证通过前不清除本地隔离副本。
`external_artifacts/incoming` 源输入、Git 历史和归属不明工作树不属于自动清理范围。
规范升级不直接改写历史包。新建/修改时采用适用的新规则，需要升级则另出版本并保留来源和新证据。

依据：[归档记录](../records/2026-09-05-generated-artifact-retention-review.md)、
[当前头测试](../../tests/test_current_task_artifact_heads.py)。

<a id="val-008"></a>
### VAL-008 — 回放协议与基线校准

适用于以记录轨迹验证场景、资产回归或训练数据的工作。动作数值相同不等于执行等价。

- 绑定原记录、资产、配置、初始化/预热、客户端和转换版本及哈希；分别记录手臂、夹爪、底座的
  控制类型、绝对/相对语义、坐标系和单位。允许分段切换，不能凭字段名或其他任务默认值补齐缺失标志。
- 记录实际物理dt、动作周期/保持映射、分块边界、渲染方式、终止及尾帧处理。8步/30步分块、
  特定倍率与容差只属于已验证来源，不是通用默认。不得把编码FPS或控制器累积量单独当原采样时钟证明。
- 声称新资产导致旧成功退化前，先在对应旧包校准执行协议，核对已执行命令、观察状态、结果及画面。
  基线不能复现时，标明未解决的执行/环境差异，不据此直接判资产退化或排除历史成功。
- 原记录缺字段时，将推断依据、歧义、逐段映射及实测覆盖范围显式保存；不得标成原始实录。
  状态、动作与RGB逐帧对齐；格式兼容用的重复观察不算新的物理采样，原采样时间未知时不虚构频率。
- 不同自然成功终止长度应分别记录：共同前缀可比较，不得仅因长度不同判运动失真；也不得忽略
  共同帧的真实差异、未执行尾段、异常终止或尾帧保持。所需精度按验证目的声明，不统一要求任意引擎逐位一致。
- 分别声明记录动作回放、历史过程复现、记录状态渲染和在线策略评测的资格。旧故障未复现时，
  新版不再出现该故障不能独立证明因果修复。

协议可记录在现有交付说明/数据元信息中，不要求新增接收方辅助脚本或修改模拟器核心。
历史包按VAL-006保持原字节；文档勘误追加，真实内容修复另出版本。
依据：[水浴原版回架校准](../records/2026-10-14-task12-old-rack-reproduction.md)、
[定向交付影响审计](../records/2026-10-15-replay-protocol-delivery-impact-audit.md)。

## 推荐做法

<a id="val-007"></a>
### VAL-007 — 交付前按对象与证据清单复查

按能力检查资格、按变化选择验证、按最终字节绑定证据。给接收者清楚的入口、完整路径、目标版本、读取说明和已知限制。
已声明的 WARN 不应在摘要或任务教学中变成无条件成功描述。
