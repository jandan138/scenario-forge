# 规范维护流程与模板

状态：当前；流程责任由做设计/实现变更的人或 Agent 承担。
本版不新增自动改写、漏更阻断检查、规范校验器或人工签批环节。

## 日常变更流程

1. **开始前读规范**：从 [入口](README.md) 选择主题，记录本次适用的规则编号、对象/接口/runtime 范围。
2. **说明变化**：在设计提案或任务记录写明改变了什么、影响哪些规则；未验证的想法不改成当前准则。
3. **按类型验证**：采用 [VAL-002](validation-and-delivery.md#val-002)；复用证据必须仍匹配范围和内容。
4. **验证后同步**：同一实现者在同一组变更中更新规则、必要操作说明、引用与日期记录。规则没有通用变化时，写明“规范无需变更”及原因。
5. **交付前复查**：正文只有一份权威来源；例子和参数不冒充通用要求；记录的验证版本、限制和受影响入口一致。

“规范会更新”是上述工作职责，不是监听 `docs/design` 后自动生成的后台行为。
普通拼写、排版或链接修正按文档变化核对，不触发整套模拟器验证。

## 哪些内容可以成为正式规则

- 已有硬边界或正式接口：引用其权威定义，标明是职责/契约要求，不冒称来自某次运行实验。
- 有测试与适用运行证据的制作方式：写明对象类型、版本、测试和记录后提炼；证据只支持案例范围时不扩大范围。
- 尚无实现/证据的能力、未经确认的版本兼容或未解释冲突：留在 `design` 提案或“未覆盖”，不提升为已验证规则。
- 单任务秒数、颜色和尺寸：通常属于任务配置/教程。除非已经是明确的域/API 契约，不写成全仓库硬默认。

现有证据可通过已提交的 `docs/records`、测试和脚本定位；大型运行报告可由记录内的路径与哈希定位，
不要求为了整理规范将大型输出提交 Git，也不伪造没有保存的验证。

## 权威正文与历史记录

场景制作规则正文放在 `standards`。`design` 保留理由和提案，`operations` 保留命令和教程，二者引用规则编号。
核心包/schema/API 契约继续在其现有设计文档，规范只引用；若同一文档混有 API 与制作规则，保留接口定义，迁出可独立的制作要求。

保留旧路径作为解释或迁移入口，避免历史链接断开。已有日期记录不重写；新记录说明旧规则被什么替代。
Git 提交是规范版本依据。任务的设计/交付记录注明已有的规范基线提交、规则编号及本次同步变化；
规范和任务在同一组变更中提交时由 Git 历史共同追溯，不要求文件提前写入自身尚不存在的提交哈希。
首次整理前的旧包没有规范提交时，
记录它原本的来源和证据即可，不补造“符合首版规范”的认证。升级旧任务时另出版本。

规则正文有冲突时先核对范围和版本，依据实现/验证记录解决并记下原因；不得因时间戳较新而忽略项目硬边界。
推荐项的例外记录任务理由和验证；强制项只在该规则本身明示的例外条件内豁免，不能用备注绕过有效性或资格要求。

## 稳定编号和替代

编号前缀为 `ASSET`、`USD`、`ART`、`MAT`、`STATE`、`VAL`，主题内编号不复用。
明确锚点如 `#art-001` 保持稳定，标题措辞变化不改变引用入口。
小幅澄清保留编号并记版本；行为被替代时保留该编号的替代说明并链接新规则，不能让历史编号指向不相干内容。
不另维护一套手工 semver 注册表；从 Git 查看某次交付所依据的正文。

## 主题文档模板

```markdown
# 主题名称

状态：当前。
适用范围：对象类型、契约/接口版本、目标 runtime；明确未覆盖范围。

## 强制要求

<a id="topic-001"></a>
### TOPIC-001 — 规则标题

规则正文。说明适用条件、不可省略的要求及明示例外。
依据：权威接口链接；对应测试；已提交的验证/决策记录。

## 推荐做法

<a id="topic-002"></a>
### TOPIC-002 — 推荐标题

成熟做法与理由，说明哪些情况可采用其他实现以及需要什么证据。

## 已知限制与变更记录

说明未验证对象/runtime、已接受限制和原规则替代关系。
YYYY-MM-DD：变更摘要，链接日期记录；版本以 Git 提交为准。
```

## 设计/任务记录中的规范处理模板

```markdown
规范依据：<已有规范基线 Git 提交或首次整理前的来源记录；同次规范变更一并说明>
涉及规则：<例如 MAT-002、STATE-003>
变化：<行为变化、适用范围或“规范无需变更”及原因>
验证：<测试/运行时/渲染/闭包，版本、文件与哈希或已提交记录链接>
限制或例外：<没有则明确写无；不能代替验证>
同步内容：<规范、design 引用、operations 教程、交付说明>
```

## 本次建立的边界

初始迁移只引用现有证据，不改变包 API、场景控制、资产或已交付 ZIP。
仅更新已有受文档迁移影响的测试；不为“同步规范”增加新的 CI 检查。
后续实现者按流程维护，不需要额外向用户重复请求已授权范围内的文档同步许可。
