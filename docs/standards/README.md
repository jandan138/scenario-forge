# 场景制作规范：当前准则与阅读入口

状态：当前；首批整理日期：2026-09-08。版本以 Git 提交为准。

这里是 Scenario Forge **场景制作全流程的权威准则存放地**。
面向制作或修改场景的人与 Agent，覆盖资产接入、USD、articulation、材质/液体、交互状态、验证和交付。
它整理项目已验证的做法与现有职责约束，不是完整 OpenUSD 官方标准，也不宣称对所有模拟器有效。

| 制作阶段 | 正式规则 | 阅读重点 |

| 选资产、接入外部工具 | [资产接入](asset-intake.md) | 谁负责生产与修复、资格与哈希、可继承的能力 |

| 使用带关节的设备 | [Articulation](articulation.md) | 固定基座 v2、刚体与关节、VR 注册、随机化 |
| 制作假液体或改变外观 | [材质与液体](materials-and-liquids.md) | Shader 属性、连续变色、几何分层、物理边界 |

首次制作场景先读本页、资产接入和验证与交付，再按实际任务读取相关主题。
一个水浴任务可能同时使用 PBD 水浴和视觉假样液；一个带旋塞的任务也未必采用固定基座 v2 的标准层级。
必须按**能力、结构和验证范围**选择规则，不能仅凭任务名称套用。

## 文档的权威关系

| 位置 | 职责 |
|---|---|
| `docs/standards` | 当前场景制作准则：应该遵循什么、适用于哪里、依据是什么 |
| `docs/design` | 场景设计理由、比较与待验证方案；相关正式规则引用本目录 |
| `docs/operations` | 操作步骤、命令和具体任务教学；引用规则，不独立维护另一份准则 |
| `docs/records` | 当时的决定、实现、证据和限制；历史事实不随新版规则重写 |

**核心包、schema、API 和外部适配器契约仍由现有设计文档定义**，不在本次迁移范围。
例如 [包格式](../design/package-v0.2.md)、[USD 编译器接口](../design/usd-scene-compiler.md)、
[来源绑定](../design/scenario-source-bindings.md)、[场景 overlay 接口](../design/scene-asset-overlays.md)
与[生产者整场景入口](../design/producer-composed-interactive-scenes.md)。规范库引用这些契约，不复制字段定义或自行覆盖其版本。

项目最高层职责边界仍见 [AGENTS](../../AGENTS.md) 与 [README](../../README.md)。
遇到内容冲突，先检查对象类型、接口版本和运行时；无法解释的冲突要在设计/任务记录中列明并解决，
不能选择“文件更新日期较新”的一方就宣布验证通过。

## 强制要求与推荐做法

- **强制要求**：适用范围内的正确性、职责与证据约束。项目硬边界、无悬空关节引用、证据与交付内容一致等不能靠备注变成合格。
- **推荐做法**：已有成功经验；可以采用其他实现，但需说明目的、差异与对应验证。
- 规则有稳定编号，例如 `ART-002`、`MAT-003`。引用编号和主题文件，避免复制整段正文。
- 验证依据可能是契约、测试或特定运行结果，三者作用不同。没有 runtime/render 证据就不填写“已运行/已目视通过”。

## 更新与采用

维护依靠 [工作流程](maintenance.md)：做改动的实现者在相应验证后，同步规范、操作说明与记录。
本版没有自动改写正文、漏更阻断器、额外 CI 门槛或新增人工签批要求。

当前规则约束新建任务和后续修改。旧包保留原字节与证据，必要时另出新版本；
本次整理不追认所有旧包符合本规范，也不自动重建它们。
