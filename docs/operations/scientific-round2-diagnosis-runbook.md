## 不混淆诊断与交付

1. 以原问题视频、原动作、结果时间与对应 reset 日志区间绑定案例。当前代码 HEAD 不能代替原评测的历史依赖闭包。
2. 区分物理现象、操作失败、评分异常和设计建议。二维重叠不能单独证明穿透；合法浮力也不自动是仿真故障。
3. 先校准实际原生步、动作语义、初始化和耗尽后的处理，见 [VAL-008](../standards/validation-and-delivery.md#val-008)。视频 FPS、动作数和物理 Hz 分开记录。
4. 故障观测可以让未修改的原生评测自行结束，同时完整保留 SDK 错误；这不等于无错误验收。不要把助手的 fail-fast 截断误写为原生任务必然无法继续。
5. 参数“USD 写入成功”与“后端实际生效”分别验证。读取低层 physics tensors；GeometryPrimView 同名 offset getter 可能只读 USD。后端最终合法也不证明中间 SDK 错误无害。
6. 回放未达到待测评分阶段时，不能以最终总分给新 metric 下结论。受控真实 mesh 测试和完整策略回归分别保留。

## 私有候选的最小检查

- 按 [USD-001](../standards/usd-layout.md#usd-001) 核对新入口的有效根元数据及自定义渲染设置，不能仅比较已有 Prim 的 physics 属性。
- 核对 authoring 采样器、烘焙点与 task data 恢复的先后关系。初始化粒子数变化不自动是运行中故障；颜色身份缓存必须适应初始化，并对显色后的身份变化失败关闭。
- 不让着色数组与 PhysX 动态拓扑失配。独立显示网格必须无物理 API，来源于实际流体表面；组件分色成功不等于自然反应/任务成功。
- 按 [STATE-002](../standards/task-state.md#state-002) 用实际 native tick 去重计时；不能以 API 名称或固定倍数补偿推断。
- 水浴对照同时审计浴水保留、样液保留、真实浸入状态、刚体接触和干组控制。减弱水作用但让水漏走的候选无浮力改善资格。
- 短释放 COM 拟合只是短窗净加速度证据，不是静态浮力传感器。几何门槛不满足时保留失败，修订测量协议应对所有组一致且另留记录。
